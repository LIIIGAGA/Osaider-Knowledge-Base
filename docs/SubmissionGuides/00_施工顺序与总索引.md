# Submission V2 分步施工手册：总索引

这套手册用于把现有的右上角三槽 Submission 系统，升级为中央圆形上缴与骰子鉴定界面。

所有文档都按实际施工顺序排列。建议完成一份、测试通过一份，再继续下一份。

## 开始前的重要约定

1. 保留现有 `BP_CoreDevice`、`SubmittedItems`、`AreAllSlotsFilled`、Inventory 和模块 Reveal 系统。
2. 不创建新的模块父类，不重新引入 `BP_ModuleBase`。
3. 故事模块继续使用“预先放置、初始隐藏、鉴定后 Reveal”，不要改成运行时 `SpawnActor`。
4. 文档中的 `ItemDataType` 不是要求你新建的类型；它代表你当前 `SubmittedItems` 数组的元素类型。
5. 如果你的项目节点名称与文档略有不同，以当前已经能够正常运行的旧功能为准。
6. 每改一个 Blueprint 都先 Compile，再 Save。
7. 首次教学只由 `BP_CoreDevice.SubmissionTutorialState` 控制；不要再在模块、Widget 或 PlayerController 中各自保存一份“教学是否完成”。
8. 三个初始模块在“物品成功加入 Inventory”后上报；`RevealModuleGroup`、`HideModuleGroup` 和 `SetAlreadyRevealed` 都不负责触发教学。
9. 教学使用三层防重复：`bCountsTowardInitialUnlock`、`bHasReportedInitialTrigger`、全局 `SubmissionTutorialState`。

## 推荐施工节奏

不要一次完成所有内容。建议按以下检查点推进：

1. 完成 01–03：三个指定模块在 Inventory ADD 后各上报一次，D 键能安全调用测试 Print。
2. 完成 04：教学状态依次经过 Waiting、Pointing、Completed；完成后 D 直接打开。
3. 完成 05：中央 UI 能独立打开、关闭，不影响世界。
4. 完成 06：三个槽位能正确选择和显示物品。
5. 完成 07：点击测试事件能产生合法 `PendingRevealModule`，但模块不显示。
6. 完成 08：中央按钮能播放一次 1.5 秒旋转。
7. 完成 09：旋转停止后才显示模块并淡出。
8. 完成 10–11：连续完成至少三轮，不产生重复或卡死。

## 调试原则

施工期间保留临时 `Print String`：

- `[Submission] Initial Trigger Count = X`
- `[Submission] Tutorial State = StateName`
- `[Submission] Availability = True/False`
- `[Submission] Open Requested`
- `[Submission] Slot N Assigned`
- `[Submission] Prepare Check Success`
- `[Submission] Pending Module = ActorName`
- `[Submission] Rotation Finished`
- `[Submission] Reveal Committed`

全部测试通过后再移除或关闭这些调试输出。
