# 第 11 部分：完整测试与排错

## 本部分目标

用一套固定测试顺序验证整个 Submission V2，避免只测试“正常点击一次”而遗漏状态、时序和后续循环问题。

## 1. 测试前准备

在关键节点保留临时 Print String：

```text
[Submission] Initial Trigger Count = X
[Submission] Tutorial State = StateName
[Submission] Availability = True/False
[Submission] D Pressed
[Submission] Launcher Clicked
[Submission] Panel Opened
[Submission] Slot N Assigned = ItemID
[Submission] Prepare Success/Failure
[Submission] Pending Module = ActorName
[Submission] Rotation Started
[Submission] Rotation Finished
[Submission] Reveal Committed
[Submission] Panel Closed
```

不同 Print 使用不同颜色：

- 输入/UI：青色；
- Prepare：黄色；
- Reveal：绿色；
- Error：红色。

## 2. 测试 A：游戏初始状态

进入 PIE 后，不与任何初始模块完成交互、不领取模块物品。

预期：

- 三个初始模块可见。
- Submission Prompt 不显示。
- 红色图标不可用或低亮。
- 按 D 不打开面板。
- `TriggeredInitialModules.Length == 0`。
- `SubmissionTutorialState == CollectingInitialItems`。
- `bCheckInProgress == False`。

## 3. 测试 B：同一初始模块重复执行发放事件

通过正常交互或调试连续多次进入第一个模块的 `GrantItem_Event`。

预期：

- Count 只从 0 变成 1。
- 不会增加到 2 或 3。
- Submission 仍不可用。

如果失败：

- 检查 `Add Unique`；
- 检查模块 `bHasReportedInitialTrigger`；
- 检查通知是否接在重复事件或 Tick。
- 检查通知是否确实位于 Inventory `ADD` 后，而不是 Reveal/Hide 函数。

## 4. 测试 C：三个模块但物品不足

让三个不同初始模块都完成上报，但通过调试方式确保 Inventory 少于三个有效物品。

预期：

- Trigger Count 为 3。
- Availability 仍 False。
- D 不打开。

## 5. 测试 D：第一次解锁与任意入口直接打开

让 Inventory 达到三个有效物品。

### 测试 D-1：首次使用 D 键

重新开始一次 PIE，预期顺序：

1. Availability 变 True。
2. State 从 Collecting 变为 `WaitingForFirstD`，D Prompt 出现。
3. 第一次按 D。
4. 面板立即打开，只创建一个 Widget。
5. State 变为 `Completed`。
6. D Prompt 隐藏，且本局不再出现。
7. 鼠标可操作 UI。
8. 世界点击与相机被锁定。
9. 外圈不会自动旋转，模块不会自动 Reveal。

### 测试 D-2：首次使用右上角红色图标

重新开始一次 PIE，再次取得三个初始物品，但这次不要按 D：

1. Availability 变 True。
2. D Prompt 出现，右上角红色图标同时可点击。
3. 点击右上角红色图标。
4. 它调用与 D 相同的 `HandleOpenSubmissionInput`。
5. 面板立即打开，只创建一个 Widget。
6. State 变为 `Completed`。
7. D Prompt 隐藏，且本局不再出现。
8. 外圈不会自动旋转，模块不会自动 Reveal。

### 测试 D-3：入口职责

分别通过 D 和红色图标打开面板，确认：

- 两者打开的是同一个 `SubmissionPanelRef`；
- 两者都只负责打开面板；
- 两者都不会打开 Inventory；
- 两者都不会调用 `PrepareDiceCheck`；
- 只有中央 `Button_Check` 会开始 1.5 秒旋转和鉴定。

## 6. 测试 E：三个槽位与 Inventory

分别测试：

### Slot 0

- 点击左上槽。
- Inventory 打开。
- 选择物品 A。
- A 图标出现在左上。

### Slot 1

- 选择 B，出现在右上。

### Slot 2

- 选择 C，出现在下方。

预期：

- A/B/C 不串位。
- 重复物品被禁用。
- 三槽满后中央按钮 Enabled。
- 槽位未满时中央按钮 Disabled。

## 7. 测试 F：替换物品

点击已经填好的 Slot 1，重新打开 Inventory，选择物品 D。

预期：

- 只有 Slot 1 从 B 换成 D。
- A 与 C 不变。
- B 可以重新变成可选择状态。
- 三槽仍然 Ready。

## 8. 测试 G：Prepare 不提前 Reveal

点击中央按钮，立即在动画中途 Pause PIE。

检查：

- `SubmissionState == Checking`。
- `bCheckInProgress == True`。
- `PendingRevealModule` 有效。
- Pending Actor 仍 Hidden。
- Collision 仍关闭。
- `SubmittedItems` 仍保留。
- 三个槽位不能点击。
- D 无效。

任何模块提前显示都表示 Prepare 与 Commit 没有真正拆开。

## 9. 测试 H：1.5 秒动画

使用屏幕录制或秒表确认：

- 从按钮按下到旋转停止约 1.5 秒；
- 开始缓慢；
- 中间加速；
- 结束减速；
- 外圈不晃动；
- 外圈不裁切；
- 三个槽位、物品图标和中央按钮不转。

## 10. 测试 I：Commit 与 Fade 顺序

观察 Print：

```text
Rotation Finished
Reveal Committed
Panel Closed
```

顺序不能改变。

视觉预期：

1. 外圈停止。
2. 新模块出现。
3. 面板开始淡出。
4. 游戏输入恢复。

## 11. 测试 J：Reveal 模块完整性

对新显示模块检查：

- 主模型可见；
- Collision 启用；
- InteractionPoint 可见并可点击；
- OwnedInteractionPoints 正确引用模块；
- Tick 和局部机制正常；
- CameraSpline 交互正常；
- `bAlreadyRevealed` 已更新；
- Actor 已加入 `SpawnedModules`。

## 12. 测试 K：第二轮与第三轮

### 第二轮

- Reveal 并完成一个后续模块的物品获取。
- 确认它的 `bCountsTowardInitialUnlock=False`。
- 确认 `SubmissionTutorialState` 仍是 Completed。
- D Prompt 与红图标 Attention 都不能出现。
- 满足物品条件后按 D，应直接打开，不再播放首次教学。
- 关闭面板后点击右上角红色图标，也应直接打开同一个面板。
- 完成鉴定，Reveal 新模块 B。

### 第三轮

- 再次完成。
- Reveal 新模块 C。

预期：A、B、C 不重复。

### 教学全局兜底测试

在 State=Completed 时，通过调试按钮强制调用一次：

```text
NotifyInitialModuleTriggered(任意 Actor)
```

预期：

- Triggered 数组不增加；
- State 仍是 Completed；
- 不显示 D Prompt；
- 不播放红色入口 Attention。

### 真正 Spawn 新实例测试（仅当项目未来使用 SpawnActor）

- 新 Actor 的 `bCountsTowardInitialUnlock` 默认必须为 False；
- 即使手动错误设为 True，CoreDevice Completed 状态也必须拒绝通知；
- 不得重播教学。

## 16. 常见症状排错表

### D 没反应

检查顺序：

1. `IA_OpenSubmission Started` 是否触发。
2. Mapping Context 是否存在。
3. `CanOpenSubmission` 是否 False。
4. `bUIInteractionLocked` 是否错误为 True。
5. `bCheckInProgress` 是否卡住。

### 第一次 D 没有直接打开

新方案中，条件满足后的第一次 D 本来就应该直接打开。如果没有打开，检查：

1. State 是否为 `WaitingForFirstD`。
2. `HandleOpenSubmissionInput` 的 Waiting 分支是否仍调用旧 `GuidePlayerToSubmissionLauncher`。
3. 是否仍执行 `SetSubmissionTutorialState(PointingToLauncher)`。
4. Waiting 分支是否已经连接 `OpenSubmissionPanel`。

### 第一次打开后仍显示 D Prompt

1. `OpenSubmissionPanel` 的“复用 Widget”和“首次 Create Widget”两条成功路径是否都设置 Completed。
2. `SetSubmissionTutorialState(Completed)` 是否位于成功打开之后。
3. HUD 是否已经绑定 `OnSubmissionTutorialStateChanged`。
4. HUD Completed 分支是否调用 `HideDPrompt`。

### 红色图标能打开，但 D 不能打开（或反过来）

1. 两个入口是否都调用同一个 `HandleOpenSubmissionInput`。
2. HUD 的 `OnClicked` 是否还复制了一套旧 Switch/CanOpen 逻辑。
3. 是否有其中一个入口绕过了 `CanOpenSubmission`。

### 第二轮又出现 D 教学或红图标提示

1. `SubmissionTutorialState` 是否被 Reset 函数重置。
2. HUD 的 Completed 分支是否仍在显示 Prompt。
3. 是否还在使用 PlayerController/Widget 的旧教学 Boolean。
4. 新模块的 `bCountsTowardInitialUnlock` 默认是否错误为 True。
5. `NotifyInitialModuleTriggered` 是否错误连接到 `RevealModuleGroup`。

### 点击圆不打开 Inventory

1. Image 是否拦截 Hit Test。
2. Button ZOrder。
3. `SubmissionState` 是否允许。
4. Inventory Class 是否有效。

### Inventory 选完没有回填

1. `bOpenedForSubmission`。
2. `SubmissionPanelRef` 是否 Valid。
3. `ActiveSlotIndex` 是否正确。
4. CoreDevice Setter 是否拒绝。
5. Icon 字段是否有效。

### Check 永远不启用

1. `AreAllSlotsFilled`。
2. 数组长度是否 3。
3. 空值判断是否正确。
4. `RefreshSubmissionState` 是否调用。

### 动画开始就 Reveal

1. Prepare 中是否仍有 Reveal。
2. 旧 Enter/BeginCheck 是否还执行。
3. 中央按钮是否同时调用旧 BeginCheck。

### 动画结束不 Reveal

1. Animation Finished 绑定。
2. Pending Actor Valid。
3. Interface Target。
4. Actor 是否实现 `BPI_SpawnReveal`。
5. Tag 是否有候选。

### 模块可见但不可交互

1. 是否只 Unhide 主 Actor。
2. Collision 是否打开。
3. OwnedInteractionPoints 是否 Reveal。
4. `OwningModuleRef` 是否设置。
5. Tick 是否启用。

### 面板关闭后不能操作

1. Input Mode 是否恢复 Game Only。
2. `bUIInteractionLocked` 是否 False。
3. HoverTrace Branch。
4. 鼠标显示和焦点状态。
