# 第 02 部分：初始模块、全局教学状态与 Submission 解锁

## 本部分目标

实现以下准确规则：

1. 只有关卡开始时指定的三个初始模块有资格推进教学。
2. 只有物品已经成功加入 Inventory 后，模块才上报一次。
3. 同一个模块实例不能重复上报。
4. 第三个初始物品取得后，显示首次 D 教学。
5. 教学完成后，无论后续 Reveal 其他模块、重复循环，甚至意外调用通知，都不能再次触发教学。

最终使用三层保护：

```text
模块是否属于初始三个：bCountsTowardInitialUnlock
→ 当前模块实例是否已经报告：bHasReportedInitialTrigger
→ 全局教学是否仍在收集阶段：SubmissionTutorialState
```

## 1. 创建教学状态枚举

在 Content Browser：

1. 右键 → Blueprints → Enumeration。
2. 命名：`E_SubmissionTutorialState`。
3. 添加四个值：

```text
CollectingInitialItems
WaitingForFirstD
PointingToLauncher
Completed
```

含义：

- `CollectingInitialItems`：玩家还没有从三个指定初始模块全部取得物品。
- `WaitingForFirstD`：条件已满足，HUD 正在提示玩家按 D。
- `PointingToLauncher`：玩家已经按 D，正在提示点击右上角红色图标。
- `Completed`：首次教学已完成，以后 D 直接打开 Submission。

## 2. 在 `BP_CoreDevice` 新增变量

### `SubmissionTutorialState`

- 类型：`E_SubmissionTutorialState`。
- 默认值：`CollectingInitialItems`。
- 这是当前游戏流程中唯一可信的教学状态。

### `TriggeredInitialModules`

- 类型：Actor Object Reference Array。
- 默认：空数组。
- 只记录三个指定初始模块中已经成功发放物品的 Actor。

### `RequiredInitialModuleCount`

- Integer，默认 `3`。

### `bSubmissionAvailable`

- Boolean，默认 `False`。

### `bCheckInProgress`

- Boolean，默认 `False`。

### `MinimumSubmissionItemCount`

- Integer，默认 `3`。

不要再在 PlayerController、HUD 或 `WBP_SubmissionPanel` 中建立另一份 `bFirstSubmissionTutorialComplete`。所有地方都读取 `BP_CoreDevice.SubmissionTutorialState`。

## 3. 创建两个 Event Dispatcher

### `OnSubmissionTutorialStateChanged`

输入：

- `NewState`：`E_SubmissionTutorialState`。

### `OnSubmissionAvailabilityChanged`

输入：

- `bIsAvailable`：Boolean。

HUD 通过它们更新 D Prompt、红色入口和教学动画。

## 4. 创建统一状态修改函数

在 `BP_CoreDevice` 新建 Function：

`SetSubmissionTutorialState`

输入：

- `NewState`：`E_SubmissionTutorialState`。

节点：

```text
SubmissionTutorialState == NewState
→ Branch
  True → Return
  False
    → Set SubmissionTutorialState = NewState
    → Call OnSubmissionTutorialStateChanged(NewState)
    → RefreshSubmissionAvailability
```

不要从外部 Blueprint 直接 Set 这个变量；统一调用该函数。

## 5. 创建 `NotifyInitialModuleTriggered`

在 `BP_CoreDevice` 新建 Function：

`NotifyInitialModuleTriggered`

输入：

- `ModuleActor`：Actor Object Reference。

函数入口首先检查全局教学状态：

```text
SubmissionTutorialState == CollectingInitialItems
→ Branch
  False
    → Print String（调试可选）：Initial report ignored — tutorial not collecting
    → Return
  True
    → Is Valid(ModuleActor)
    → Branch
      False → Return
      True
        → Add Unique(ModuleActor) 到 TriggeredInitialModules
        → Print Initial Trigger Count
        → TryUnlockFirstSubmissionTutorial
```

这道入口检查非常重要。教学进入 `WaitingForFirstD`、`PointingToLauncher` 或 `Completed` 后，任何模块再调用该函数都会立即结束。

## 6. 在模块 Actor 添加两层实例保护

在会发放物品的模块 Blueprint 中新增：

### `bCountsTowardInitialUnlock`

- Boolean，默认 `False`。
- 勾选 `Instance Editable`。
- 只有关卡开始时的三个指定模块实例设为 `True`。
- 后续等待骰子 Reveal 的模块保持 `False`。
- 如果以后真的 `SpawnActor` 创建新实例，因为 Class Default 为 `False`，新模块默认也不会推进教学。

### `bHasReportedInitialTrigger`

- Boolean，默认 `False`。
- 不勾选 `Instance Editable`。
- 只防止当前 Actor 实例重复上报。

注意：`bHasReportedInitialTrigger` 不能代替 CoreDevice 的全局状态。新 Actor 实例会重新得到默认值 `False`，所以必须保留三层保护。

## 7. 正确插入通知的位置

根据当前蓝图，正确位置是模块 EventGraph 中的：

```text
GrantItem_Event
→ Cast To BP_GameInstance
→ ADD（Granted Item 加入 Inventory Items）
→ 【插入初始模块通知逻辑】
→ Create WBP Item Popup Widget
→ Add to Viewport
→ Init Item
```

也就是放在 Inventory `ADD` 节点之后、`Create WBP Item Popup Widget` 之前。

不要放在以下位置：

- `BeginPlay`；
- `RevealModuleGroup`；
- `HideModuleGroup`；
- `SetAlreadyRevealed`；
- Tick；
- 仅仅显示 InteractionPoint 的逻辑。

原因：Reveal 只代表模块出现，不代表玩家已经完成交互并拿到物品。

## 8. 模块侧完整节点连接

把原来从 Inventory `ADD` 到 `Create WBP Item Popup Widget` 的白色执行线断开，在中间插入：

```text
ADD Inventory Item
→ Branch(bCountsTowardInitialUnlock)

False
→ TryUnlockFirstSubmissionTutorial
→ Create WBP Item Popup Widget（继续原逻辑）

True
→ Branch(bHasReportedInitialTrigger)

  True
  → TryUnlockFirstSubmissionTutorial
  → Create WBP Item Popup Widget（继续原逻辑）

  False
  → 获取 BP_CoreDevice 引用
  → Is Valid(CoreDeviceRef)
  → Branch
    False
    → 不修改 bHasReportedInitialTrigger
    → Create WBP Item Popup Widget（继续原逻辑）

    True
    → Set bHasReportedInitialTrigger = True
    → NotifyInitialModuleTriggered(Self)
       （Notify 内部会调用 TryUnlockFirstSubmissionTutorial）
  → Create WBP Item Popup Widget（继续原逻辑）
```

确认 `CoreDeviceRef` 有效后，先 Set `bHasReportedInitialTrigger = True`，再调用通知，以防同一执行流程被短时间重复进入。如果 CoreDevice 引用无效，不要 Set 为 True，这样修复引用后仍有机会重新上报。

如果模块已有可靠的 `CoreDeviceRef`，直接复用。否则可以暂时：

```text
Get Actor of Class(BP_CoreDevice)
→ Cast / 保存引用
```

但不要在 Tick 中反复查找。

## 9. 设置关卡中的三个初始实例

回到关卡：

1. 选中第一个初始模块 Actor。
2. Details 中勾选 `bCountsTowardInitialUnlock`。
3. 对第二、第三个初始模块重复。
4. 检查所有等待骰子 Reveal 的模块，该值必须保持 False。

判断依据不是模块 Class，而是关卡中的具体 Actor 实例。

## 10. 获取有效 Inventory 物品数量

从真正保存 Inventory 的位置读取数组。当前画面显示物品保存在 `BP_GameInstance.Inventory Items`，因此优先从这里读取。

在 `BP_CoreDevice` 创建：

`GetValidSubmissionItemCount`

输出：Integer。

第一版可使用：

```text
Get Game Instance
→ Cast BP_GameInstance
→ Inventory Items Length
```

如果不是所有物品都能上缴，再遍历数组排除无效类型。

## 11. 创建 `RefreshSubmissionAvailability`

局部变量：

- `bOldAvailability`：Boolean。
- `InitialCount`：Integer。
- `ValidItemCount`：Integer。
- `bTutorialGateOpen`：Boolean。

`RefreshSubmissionAvailability` 不负责把教学从 Collecting 推进到 Waiting。为了避免函数互相调用形成执行递归，把“首次解锁检查”单独放在 `TryUnlockFirstSubmissionTutorial`，由以下位置调用：

- `NotifyInitialModuleTriggered` 末尾；
- 普通物品成功加入 Inventory 后。

`RefreshSubmissionAvailability` 只计算当前是否允许打开：

```text
bOldAvailability = bSubmissionAvailable
→ bTutorialGateOpen = SubmissionTutorialState != CollectingInitialItems
→ ValidItemCount >= MinimumSubmissionItemCount
→ NOT bCheckInProgress
→ Boolean AND
→ Set bSubmissionAvailable
→ bOldAvailability != bSubmissionAvailable
→ Branch
  True → OnSubmissionAvailabilityChanged(bSubmissionAvailable)
  False → 不广播
```

首次教学完成后，不再依赖 `TriggeredInitialModules.Length` 反复触发教学；全局状态已经成为永久闸门。

## 12. 创建 `TryUnlockFirstSubmissionTutorial`

在 `BP_CoreDevice` 新建 Function：

```text
SubmissionTutorialState == CollectingInitialItems
→ Branch
  False
    → RefreshSubmissionAvailability
    → Return
  True
    → TriggeredInitialModules.Length >= RequiredInitialModuleCount
    → GetValidSubmissionItemCount >= MinimumSubmissionItemCount
    → AND
    → Branch
      False
        → RefreshSubmissionAvailability
      True
        → SetSubmissionTutorialState(WaitingForFirstD)
```

`SetSubmissionTutorialState` 会刷新 Availability，因此 True 分支不要再重复刷新。

## 13. 普通 Inventory 变化后的刷新

以下时机调用：

```text
TryUnlockFirstSubmissionTutorial
```

- 初始模块物品 ADD 并完成通知后；
- 其他物品加入 Inventory 后；
- 物品被移除或消耗后。

对于非初始模块，虽然不会上报模块计数，但仍需刷新可用物品数量。

## 14. 创建 `CanOpenSubmission`

输出：`CanOpen` Boolean。

```text
bSubmissionAvailable
AND SubmissionTutorialState != CollectingInitialItems
AND NOT bCheckInProgress
AND CoreDeviceRef Valid
→ Return
```

不要在这里要求 `AreAllSlotsFilled`；玩家必须先打开面板才能填槽。

## 15. 教学完成后的永久保护

首次点击右上角红色图标后，第 04 部分会调用：

```text
SetSubmissionTutorialState(Completed)
```

此后：

- `NotifyInitialModuleTriggered` 在入口直接 Return；
- 新 Reveal 模块无法触发教学；
- 新 Spawn 的模块即使 `bHasReportedInitialTrigger=False` 也无法触发教学；
- 第二轮、第三轮只根据物品和 Check 状态决定能否打开；
- `ResetTemporarySubmissionState` 不得重置 `SubmissionTutorialState`。

如果只要求“每次新开游戏重新教学”，把状态保存在当前 `BP_CoreDevice` 即可。

如果跨关卡仍算同一局，把状态放到 `GameInstance`，由 CoreDevice 初始化时读取。

如果退出游戏再进入也不应重复教学，写入 `SaveGame`。不要在没有这个需求时提前保存为永久状态。

## 16. 本部分测试

### 初始三个模块

1. 游戏开始：State 为 `CollectingInitialItems`。
2. 第一个初始模块 ADD 物品：Count 变 1。
3. 重复调用它的 Grant 事件：教学 Count 仍为 1。
4. 第二、第三个初始模块各发放物品。
5. 三个有效物品齐全后：State 只变一次 `WaitingForFirstD`。

### 后续模块

1. Reveal 一个非初始模块。
2. 与它交互并获得物品。
3. `bCountsTowardInitialUnlock` 应为 False。
4. 不出现新的教学状态变化。

### 全局兜底

1. 将 State 设为 `Completed`。
2. 调试时强制调用 `NotifyInitialModuleTriggered`。
3. 函数应立即 Return。
4. D Prompt 和红色图标教学都不应再次出现。

## 17. 常见错误

### 模块刚 Reveal 就出现 D 教学

- 通知被错误接在 `RevealModuleGroup`；
- 删除该连接，只保留 Inventory `ADD` 后的连接。

### 第二轮重新出现教学

- HUD 或 PlayerController 仍使用旧的本地 Boolean；
- 改为读取 CoreDevice 的 `SubmissionTutorialState`；
- 检查循环清理是否错误重置了 State。

### 新 Spawn Actor 又上报

- `bCountsTowardInitialUnlock` 的 Class Default 被设成 True；
- Class Default 必须 False，仅关卡中三个初始实例手动勾选；
- CoreDevice 函数入口还必须检查 `CollectingInitialItems`。

### 物品已加入但状态不变化

- 检查通知是否接在实际使用的 `GrantItem_Event`；
- 检查 Inventory `ADD` 后是否调用通知/刷新；
- 检查读取的是否为 `BP_GameInstance.Inventory Items`。

- [ ] 唯一全局状态位于 CoreDevice。
