# 第 05 部分：视频循环、首帧与加载保护

## 本部分目标

在 `WBP_GameIntro` 中完成可靠的视频打开、循环播放、首帧切换、失败回退和资源关闭。完成后，即使视频打不开，Intro 仍然可用。

## 1. 添加 Media 引用变量

在 `WBP_GameIntro` 中添加：

| 变量名 | 类型 | 默认值 |
|---|---|---|
| `IntroMediaPlayer` | Media Player Object Reference | MP_Intro |
| `IntroMediaSource` | Media Source Object Reference | FMS_Intro_Default |
| `bMediaReady` | Boolean | false |
| `bMediaFailed` | Boolean | false |

变量分类可使用：

```text
Intro | Media
```

## 2. Event Construct 的正确顺序

不要在绑定回调之前调用 Open Source。

建立：

```text
Event Construct
→ Set bMediaReady = false
→ Set bMediaFailed = false
→ Set IMG_Video Render Opacity = 0
→ Set TXT_LoadState Text = "INITIALIZING RECORD..."
→ Bind Event to On Media Opened
    Event = HandleMediaOpened
→ Bind Event to On Media Open Failed
    Event = HandleMediaOpenFailed
→ Open Source
    Target = IntroMediaPlayer
    Media Source = IntroMediaSource
```

`Open Source` 只表示开始打开，不表示视频已经能立刻播放。

## 3. HandleMediaOpened

创建 Custom Event：

```text
HandleMediaOpened
Input: OpenedUrl (String)
```

执行流程：

```text
HandleMediaOpened
→ Set Looping
    Target = IntroMediaPlayer
    Looping = true
→ Rewind
→ Play
→ Set bMediaReady = true
→ Set bMediaFailed = false
→ Set IMG_Video Render Opacity = 1
→ Set TXT_LoadState Text = "RECORD AVAILABLE"
→ Play Animation ANIM_IntroAppear（如果尚未播放）
```

如果 `Rewind` 在某个平台返回 false，可以省略它。核心要求是先成功打开，再 Play。

## 4. HandleMediaOpenFailed

创建：

```text
HandleMediaOpenFailed
Input: FailedUrl (String)
```

执行：

```text
HandleMediaOpenFailed
→ Set bMediaReady = false
→ Set bMediaFailed = true
→ Set IMG_Video Render Opacity = 0
→ Set TXT_LoadState Text = "VISUAL RECORD UNAVAILABLE"
→ Print String "Intro media failed: " + FailedUrl
```

只在 Development / PIE 阶段保留详细 Print String。正式版本可以保留简短日志，但不要向玩家显示本地绝对路径。

Start 按钮必须继续可用。

## 5. 避免首帧黑屏

推荐图层顺序：

```text
T_Intro_Fallback
→ MT_Intro Image（初始 Opacity 0）
→ Dark Overlay
→ UI Content
```

只在 `HandleMediaOpened` 后显示视频 Image。

如果 OnMediaOpened 已触发但第一帧仍短暂为黑色，可以：

1. 保持回退图与视频首帧视觉相似；
2. 延迟 0.05–0.15 秒再淡入视频；
3. 不要让整个 Widget 等待视频才出现；
4. 不使用一张纯白的默认 Image Brush。

## 6. 循环设置

主要循环方式：

```text
OnMediaOpened
→ Set Looping(true)
```

可选的第二层保护：

绑定 `On End Reached`：

```text
HandleMediaEndReached
→ Rewind
→ Play
```

第一版通常只需要 `Set Looping(true)`。只有在目标平台实测不能循环时再加入 End Reached 保护，避免两个循环机制同时触发造成跳帧。

## 7. Widget 销毁时关闭媒体

建立：

```text
Event Destruct
→ Close
    Target = IntroMediaPlayer
```

如果 Widget 有可能在同一关卡内被创建多次，还应解除事件绑定。当前方案在切关时销毁整个 Intro 世界，Close 已足够作为第一版清理。

## 8. 音频同步

如果 `L_Intro` 中存在绑定 `MP_Intro` 的 `BP_IntroMediaAudio`：

- 音频会跟随同一个 Media Player；
- 不要再单独播放 MP4 内的重复音频；
- 循环点应检查爆音和短暂停顿；
- Start 淡出时可以先降低 Media Sound 音量，再 Close Media Player。

若需要精确的淡出音频，可以在 `BP_IntroMediaAudio` 中创建 0.4 秒 Timeline 控制 Volume Multiplier，并由 Widget 或 Intro PlayerController 调用。

## 9. 本部分验收

- [ ] 回调绑定发生在 `Open Source` 之前。
- [ ] `HandleMediaOpened` 中设置 Looping 并调用 Play。
- [ ] 视频成功后才显示 `IMG_Video`。
- [ ] 视频失败时显示静态背景和错误状态文字。
- [ ] Start 在视频失败时仍可点击。
- [ ] 视频连续播放至少三个循环。
- [ ] Event Destruct 会 Close Media Player。
- [ ] 如果使用音频，画面与声音同步。

## 常见错误

### Open Source 后立刻 Play，但没有画面

媒体打开是异步的。把 Play 移到 `OnMediaOpened` 回调中。

### 第一次能播，第二次进入 Intro 黑屏

检查上次离开时是否 Close，是否创建了多个 Widget，以及回调是否重复绑定。

### 循环点明显卡顿

先检查源视频首尾是否无缝，再降低 GOP 长度和码率。不要先用蓝图反复 Seek 掩盖编码问题。

### 加载失败后 Start 也消失

不要把整个 Content 容器与视频 Opacity 绑定。只隐藏 `IMG_Video`，保留 UI Content。
