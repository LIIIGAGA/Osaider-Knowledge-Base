# 第 08 部分：完整测试、优化与排错

## 本部分目标

在交付前验证 Intro 的媒体加载、循环、UI、输入、切关、打包和目标机器兼容性，并建立可重复的排错顺序。

不要只在 UMG Designer 或 Media Player 编辑器中验收。最终测试必须从启动 Build 开始，完成一次 Intro → Start → Gameplay 的完整路径。

## 1. 建立测试矩阵

### 运行方式

| 方式 | 主要检查内容 |
|---|---|
| Media Player 编辑器 | 源视频和 Media 资产 |
| PIE：Selected Viewport | Widget 和 Blueprint 流程 |
| Standalone Game | 分辨率、输入和窗口行为 |
| Development Build | 打包路径、日志与切关 |
| Shipping Build | 最终玩家体验 |

### 分辨率

- 1920 × 1080；
- 1600 × 900；
- 2560 × 1440；
- 2560 × 1080 或其他超宽屏；
- 目标发布的最低分辨率。

## 2. 媒体加载测试

正常文件：

1. 启动游戏。
2. 观察回退图是否立刻出现。
3. 观察视频是否平稳覆盖回退图。
4. 检查 Load State 是否正确更新。
5. 连续播放至少三个循环。

失败文件：

1. 临时让 `FMS_Intro_Default` 指向不存在的测试文件，或使用一个损坏副本。
2. 确认 `OnMediaOpenFailed` 被调用。
3. 确认静态背景仍然可见。
4. 确认 Start 仍然可点击。
5. 测试后恢复正确文件路径。

不要在提交版本中保留故意损坏的 Media Source。

## 3. 循环测试

检查至少三个循环点：

- 末帧到首帧是否闪黑；
- 宫殿位置是否突然跳动；
- 海雾运动是否反向或重置明显；
- 音频是否爆点；
- 是否出现短暂静音；
- 内存占用是否持续增长。

如果每次循环都卡顿，先优化源视频循环和编码，不要只在 Blueprint 中增加 Delay。

## 4. Start 流程测试

分别测试：

- 页面刚出现时立即点击；
- 视频尚未打开时点击；
- 视频打开失败时点击；
- 视频循环点附近点击；
- 快速双击或连续点击；
- 按住鼠标后拖出按钮再释放。

预期：

```text
Start 只触发一次
→ 淡出动画完整
→ 媒体关闭
→ 只打开一次 Prototype_07
```

## 5. Gameplay 回归测试

进入 `Prototype_07` 后：

### PlayerController

- [ ] 当前 Controller 为 `BP_NoCharacterPlayerController`。
- [ ] 鼠标显示状态正确。
- [ ] 画面中只有一个 `WBP_MouseCursor`。
- [ ] 没有 Windows 白色系统箭头。
- [ ] Intro 的 `Game and UI` 输入模式没有跨关卡残留。

### 互动

- [ ] HoverTrace 能识别 Interaction Point。
- [ ] LMB 点击正常。
- [ ] LMB 拖动正常。
- [ ] RMB 模块相机移动正常。
- [ ] Space 全局旋转正常。
- [ ] Flashlight 输入正常。

### 音频与媒体

- [ ] Intro 视频已经停止。
- [ ] Intro 音频已经停止。
- [ ] Gameplay 没有残留 `WBP_GameIntro`。

## 6. UI 与宽高比测试

检查：

- 视频没有非等比变形；
- 超宽屏裁切不会丢失主要宫殿；
- 标题和 Start 始终在 Safe Zone 内；
- 暗色遮罩不会让视频完全不可见；
- 低分辨率下文字仍然清楚；
- Start 点击区域没有被透明 Image 或 Border 阻挡；
- DPI Scaling 后按钮大小合理。

如果 16:9 正常、超宽屏主体被裁掉，应修改视频构图安全区或使用 Scale To Fit，而不是手动拉伸 Image。

## 7. 性能检查

记录 Intro 运行时：

- 视频文件大小；
- 首次打开时间；
- CPU 占用；
- GPU 占用；
- 内存变化；
- 循环后的内存是否稳定。

优化顺序：

1. 降低视频码率；
2. 从 4K 降至 1080p；
3. 从 60fps 降至 30fps；
4. 缩短视频长度；
5. 检查是否创建了多个 Media Player 或 Widget；
6. 最后再考虑平台专用媒体源。

不要开启 `Precache File` 后直接假设性能更好。长视频整体载入内存可能增加启动等待和内存压力。

## 8. 推荐排错顺序

出现问题时按以下顺序：

1. 用系统播放器确认 MP4 文件本身正常。
2. 用 Unreal Media Player 编辑器打开 `FMS_Intro_Default`。
3. 检查 `MT_Intro` 是否绑定 `MP_Intro`。
4. 检查 Widget Image Brush 是否使用 `MT_Intro`。
5. 检查回调是否在 Open Source 之前绑定。
6. 在 `HandleMediaOpened` 和 `HandleMediaOpenFailed` 加 Print String。
7. 检查当前关卡的 GameMode Override。
8. 检查 Intro 是否只创建了一个 `WBP_MouseCursor`。
9. 检查 Software Cursors 的 Default 是否为 `WBP_InvisibleSystemCursor`。
10. 检查 Start 的 DoOnce 和 Animation Finished。
11. 检查 `GameplayLevelName` 与实际地图名称。
12. 最后检查 Packaging 的 Movies 和 Maps 设置。

## 9. 常见问题总表

| 问题 | 最可能原因 | 处理 |
|---|---|---|
| Intro 完全不出现 | L_Intro 未使用 GM_Intro | 检查 World Settings 和 PlayerController Class |
| 页面出现但视频黑屏 | Media Source 未打开或 Texture 未绑定 | 先在 Media Player 编辑器测试，再检查 MT_Intro |
| Open Source 成功但不播放 | Play 调用过早 | 在 OnMediaOpened 中调用 Play |
| 视频只播放一次 | 没有 Set Looping(true) | 在 OnMediaOpened 中设置循环 |
| 视频开始前闪黑 | 没有静态回退图 | 回退图常驻下层，视频成功后再淡入 |
| 有画面但无声音 | 没有 Media Sound Component | 在 L_Intro 放置绑定 MP_Intro 的音频 Actor |
| Start 无法点击 | 视觉层阻挡 Hit Test | 把视频、遮罩和 Fade 设为不可命中 |
| 自定义鼠标不移动或无 Hover | 使用了 UI Only 或关闭了 Show Mouse Cursor | 改用 Game and UI，并保持 Show Mouse Cursor = true |
| 界面正常但没有自定义鼠标 | Intro Controller 没有更新鼠标 Widget 的位置 | Tick 中连接 Get Mouse Position Scaled by DPI → Set Position in Viewport |
| 同时出现系统箭头 | Invisible System Cursor 设置丢失 | Software Cursors 的 Default 恢复为 WBP_InvisibleSystemCursor |
| 出现两个自定义鼠标 | Controller 和 Widget 都创建了鼠标 | 只让 BP_IntroPlayerController 创建一次 |
| Start 点击两次 | 没有 DoOnce 或两处 Open Level | 保留单一导航入口 |
| 淡出动画不显示 | 提前 Open Level | 在 Animation Finished 后切关 |
| 进入游戏后输入失效 | Gameplay GameMode 或 Controller 设置错误 | 恢复 Prototype_07 原有 GameMode |
| 编辑器能播，Build 不能播 | MP4 不在 Content/Movies | 移动文件并重新保存 Media Source |
| 点击 Start 后黑屏 | Gameplay 地图未打包 | 把 Prototype_07 加入 Maps To Include |
| 超宽屏画面变形 | Image 非等比拉伸 | 使用 Scale Box 的 Fit 或 Fill |
| 循环点卡顿 | 源视频不是真正无缝或编码 GOP 过长 | 重新导出视频并检查首尾帧 |
