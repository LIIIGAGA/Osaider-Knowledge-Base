# 第 07 部分：外部 MP4 替换与打包

## 本部分目标

建立清晰的视频替换方式，设置项目默认启动关卡，并确认 Intro 地图、Gameplay 地图和 MP4 都进入发布包。

## 1. 推荐的外部视频导入方式

用户提供新的 MP4 时，推荐流程：

1. 关闭正在预览 `MP_Intro` 的 Media Player 编辑器。
2. 把新视频复制到：

```text
Content/Movies/Intro
```

3. 使用稳定文件名：

```text
Osaider_Intro_Loop.mp4
```

4. 打开 `FMS_Intro_Default`，重新选择该文件。
5. 保存 File Media Source。
6. 打开 `MP_Intro` 独立测试。
7. 运行 `L_Intro` 测试 UI、循环和 Start。

如果希望保留多个版本，可以使用：

```text
Osaider_Intro_Loop_v01.mp4
Osaider_Intro_Loop_v02.mp4
```

但正式版本应只让 `FMS_Intro_Default` 引用一个批准文件，避免不必要的媒体被打包。

## 2. 随项目打包与运行时外部文件的区别

### 方案 A：随项目打包，推荐

```text
MP4 位于 Content/Movies
→ File Media Source 引用该文件
→ 视频随 Build 发布
```

适合：

- 作品集版本；
- Vertical Slice；
- 固定 Intro；
- 需要最少部署风险的版本。

### 方案 B：运行时读取外部绝对路径，可选

```text
外部配置提供完整路径
→ File Media Source.Set File Path
→ Open Source
→ 失败时回退 FMS_Intro_Default
```

适合内部展示机器或无需重新打包的视频替换，但存在：

- 不同电脑路径不同；
- 文件可能被移动；
- 外部文件不会自动随 Build 分发；
- Windows、macOS 和主机平台路径规则不同；
- Shipping Build 权限与播放器支持需要单独验证。

Phase 1 推荐只完成方案 A。方案 B 应作为后续工具功能，不应阻塞 Intro 页面交付。

## 3. 可选的回退逻辑

如果实现运行时外部路径：

```text
Try External Path
→ Open Source
→ OnMediaOpened: 正常播放
→ OnMediaOpenFailed: Open Source(FMS_Intro_Default)
→ 默认源也失败: 显示 T_Intro_Fallback
```

需要额外 Boolean：

```text
bTriedExternalMedia
bTriedDefaultMedia
```

防止两个失败回调形成无限重试。

## 4. 设置默认启动关卡

打开：

```text
Project Settings
→ Project
→ Maps & Modes
```

建议设置：

```text
Game Default Map = L_Intro
Editor Startup Map = Prototype_07
```

这样：

- 打包游戏从 Intro 开始；
- 编辑器打开时仍直接进入当前开发关卡；
- 不影响日常模块调试速度。

如果需要专门调试 Intro，可以临时把 Editor Startup Map 改为 `L_Intro`，完成后再改回。

## 5. 把地图加入打包列表

打开：

```text
Project Settings
→ Packaging
→ List of Maps to Include in a Packaged Build
```

加入：

```text
L_Intro
Prototype_07
```

如果项目依赖其他过渡或测试地图，不要因为 Intro 施工删除原有列表。

## 6. 检查 Movies 打包

确认：

```text
Content/Movies/Intro/Osaider_Intro_Loop.mp4
```

File Media Source 路径不应引用：

- Desktop；
- Downloads；
- 外接硬盘盘符；
- OneDrive 临时目录；
- 其他开发者电脑的绝对路径。

如果 Packaging 设置中存在“排除电影文件”或自定义 Pak 规则，确认没有把 Intro MP4 排除。

## 7. 第一次打包测试

第一版先打 Development Build，而不是直接只测 Shipping。

测试顺序：

1. 在编辑器中运行 `L_Intro`。
2. 使用 Standalone Game 测试。
3. 打 Development Build。
4. 把 Build 复制到另一个目录运行。
5. 如果条件允许，在另一台电脑运行。
6. 最后打 Shipping Build。

不要只在 PIE 中确认视频可播。PIE 会访问完整的项目文件，而发布包的文件结构不同。

## 9. 本部分验收

- [ ] 新 MP4 可以通过替换 Movies 文件完成更新。
- [ ] `FMS_Intro_Default` 不引用开发电脑的临时路径。
- [ ] `Game Default Map` 为 `L_Intro`。
- [ ] `Editor Startup Map` 按开发需要设置。
- [ ] `L_Intro` 和 `Prototype_07` 均在打包地图列表中。
- [ ] Development Build 中视频正常播放。
- [ ] 把 Build 移动位置后仍能播放。
- [ ] Shipping Build 中 Intro 与切关正常。

## 常见错误

### 编辑器能播，打包版本找不到视频

最常见原因是 MP4 不在 `Content/Movies`，或 File Media Source 仍指向外部绝对路径。

### 点击 Start 后停留在黑屏

检查 `Prototype_07` 是否进入打包地图列表，以及关卡名称是否拼写完全一致。

### 更换同名 MP4 后仍播放旧画面

关闭 Media Player 编辑器，重新保存 `FMS_Intro_Default`，清理旧 Build 后重新打包。不要只覆盖已生成 Build 内部的 Pak 文件。
